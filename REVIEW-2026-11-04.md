Date: 2026-11-04. Reviewer: Claude (Sonnet 5), standing in for the Codex
review that was unavailable for this run. Scope: `git diff
origin/main...HEAD` and `git log origin/main..HEAD` on
`/Users/mi4u/Work/public/.wt/brainmd-oauth`, branch `feat/identity-oauth`,
about 40 commits ahead of `origin/main`. No push, merge, tag or release was

The branch adds optional OIDC/GitHub login (arctic + jose) next to the
existing password login, user identities, `__Host-` cookies, and per-folder
permissions that fail closed.

This review worked from a pre-computed, already-triaged finding set (no
findings were refuted). Each confirmed finding was independently verified
against the current source before a fix was written.

## Findings

### 1. `security-health-vaultdir-leak` (medium): CONFIRMED, FIXED

`GET /health` returned `{ ok: true, vaultDir: vault.root }`, registered
outside `authMiddleware`'s protected-path check (which only gates
`/api/*` and `/mcp*`), so the vault's absolute filesystem path was
readable with zero credentials, by anyone who can reach the server
(typically left open on purpose for uptime checks).

Fix: `/health` now returns only `{ ok: true }`. No code read `vaultDir`
from this endpoint.

Commit: `e231cbc`: `fix(api): stop leaking the vault filesystem path from GET /health`
Test: `server/test/health.test.ts`: new test asserts the response has
no key other than `ok` and the body never contains the vault directory
string.

### 2. `correctness-1` (high): CONFIRMED, FIXED

`authMiddleware` always seeded `identityContext` with
`localIdentity(owner.name, owner.email)` (owner config defaults:
`"brain.md owner"` / `"owner@brain.local"`), even when auth was entirely
unconfigured: no password set, no external login provider. Every such
install (the default state) had every autocommit's author line change
from the fixed `"brain.md <brain@local>"` committer identity that
v0.4.12 always produced (no `--author` was ever passed pre-branch), to
`"brain.md owner <owner@brain.local>"`. That breaks anything built
around the old identity: `git log --author` filters, scripts, CI checks.
It also contradicts this branch's own stated bar that behaviour with
OAuth disabled must match v0.4.12.

Fix: `identityContext` is now seeded with the legacy git identity
(`"brain.md"` / `"brain@local"`) when auth is fully unconfigured
(`!auth.isConfigured() && !externalLoginConfigured`), and with the owner
config identity only once a password or an external login provider is
actually configured. Password-login behaviour (which already exercised
the owner-config identity intentionally, per the existing test) is
unchanged.

Commit: `deb7d5d`: `fix(auth,git): keep the legacy git identity for fully unconfigured auth`
Test: `server/test/git.attribution.test.ts`: the "unconfigured auth"
test now asserts the commit author is `"brain.md" <"brain@local">`,
not the owner config default. The password-login test (asserting
`"brain.md owner"` / `"owner@brain.local"`) is untouched and still
passes, confirming the two paths are now correctly distinguished.

### 3. `correctness-2` (low): CONFIRMED, FIXED

`Autocommit.flush()` had an early `if (paths.size === 0) return null;`
inside the `try` block, returning straight out of the function and
skipping the end-of-function block that checks `this.rerun` and
reschedules a follow-up flush. A second caller forcing a flush (e.g. the
`/api/git/flush` route) while a first flush was already in-flight sets
`this.rerun = true` and returns immediately; if that in-flight flush then
hit the empty-paths early return, the forced flush's rerun request was
dropped and `this.rerun` stayed stuck `true` with nothing scheduled to
ever consume it.

Fix: the empty-paths case no longer returns early from inside the `try`
block. It falls through to the same end-of-function check that consumes
`rerun` / reschedules, so a forced flush that arrived mid-flush is never
silently dropped.

Commit: `3d8d2b6`: `fix(git): don't drop a forced rerun when a flush's own path set is empty`
Test: `server/test/git.autocommit-no-hang.test.ts`: new test stubs
`hasChanges()` with a controlled deferred promise, starts a flush, lets
it advance past `inFlight = true`, forces a second flush (which sets
`rerun`), resolves the first flush to "nothing changed" (empty path
set), then asserts `hasChanges()` is called again within the retry
window, proving the forced rerun actually fired instead of being lost.
Verified stable across repeated runs (not timing-flaky in the 3 runs
done here).

### 4. `tests-ops-001` (medium): CONFIRMED, FIXED

`HandoffCodeStore.consume()` checks `rec.expiresAt < Date.now()` and
rejects an expired code, but no existing test ever advanced or froze
time: only unknown-code, wrong-secret, double-consume and uniqueness
were covered. This is the one time-dependent branch gating every
external login's session issuance (a slow redirect or tab switch between
the IdP callback and the browser's exchange call turns into a silent
"invalid or expired code" failure), and it had zero coverage.

Fix: added a `Date.now()`-mocked ("fake clock") test suite: one test
issuing a code and advancing past the 60s TTL, asserting rejection even
with the correct secret hash; one boundary test pinning the strict `<`
comparison's actual semantics (valid exactly at `expiresAt`, rejected
1ms past it: the implementation treats `now === expiresAt` as not yet
expired, which the first draft of this test got backwards and which the
full suite run caught).

Commit: `a749c4f`: `test(auth): cover handoff code TTL expiry and its boundary`

### 5. `tests-ops-002` (medium): CONFIRMED, FIXED

Both `package.json` and `server/package.json` still said `0.4.12` after
40 commits adding two new runtime deps (`arctic`, `jose`), a dozen new
env vars (`BRAINMD_OIDC_*`, `BRAINMD_GITHUB_*`, `BRAINMD_PUBLIC_URL`,
`BRAINMD_OAUTH_ALLOWED_*`), new cookies, and a new login-code exchange
path. No `CHANGELOG.md` existed anywhere, and the README had no
upgrade notes.

Fix: bumped both `package.json` files to `0.5.0` (backward-compatible
feature addition). Added `CHANGELOG.md` documenting the new OIDC/GitHub
login env vars, the fail-to-start-without-an-allowlist behaviour, and
that password login and passwordless installs are unaffected unless an
operator opts in. Also documents the three fixes above as "since the 40
commits on `feat/identity-oauth`".

Commit: `945b2a7`: `chore: bump to 0.5.0, add a CHANGELOG for the OIDC/GitHub login release`

## Release readiness for v0.5.0

All five confirmed findings are fixed, each with a regression test, and
the full suite plus typecheck are green. The two correctness/security
issues that mattered most for a real upgrade are closed:

- No unauthenticated install leaks its vault path via `/health`.
- No unconfigured install (the default, no password / no external login)
  silently changes its git author identity on upgrade, which was the
  one finding that would have broken real users' existing setups without
  them opting into anything.

Nothing in this review's confirmed set blocks shipping 0.5.0. Two things
worth a human's attention before or shortly after release, not blockers:

- The `correctness-2` fix (forced-rerun-dropped) is a genuinely rare race
  (empty path set at the exact moment a forced flush landed); it was
  latent before this branch too in spirit, just newly exercised by the
  `/api/git/flush` route this branch adds. Low risk, but worth a changelog
  mention if anyone scripts against that endpoint.
- `CHANGELOG.md` is new in this release; nothing enforces it gets kept up
  to date going forward (that's a process note, not a code issue).
